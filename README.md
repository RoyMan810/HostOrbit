# HostOrbit

Self-hosted система управления Linux-серверами по [ТЗ v2.4](docs/spec/HostOrbit_Technical_Spec_v2.4.md). Прикладной Controller включает локальное создание Owner, Auth/RBAC, SQLite с Audit/Outbox, изолированные Worker/Broker, SSH observation, резервное копирование и восстановление.

## Текущее состояние

**Цель текущей сборки — стенд AC-28.** Stage0 и Stage1 Foundation приняты. Осталось проверить сквозной перезапуск тестового Docker-контейнера на отдельной Ubuntu VPS. [Критерии](docs/spec/HostOrbit_Requirements_Registry_v2.4.json) · [действующие проверки Stage1](evidence/revalidation/stage1-current/README.md).

Доступна подписанная **development**-установка на Ubuntu 24.04 и новее, amd64; native-установка проверена на 24.04 и 26.04. Единственный включённый remote adapter — read-only `host.probe`. Production mutations, A/B updates, live migration и независимая DR-приёмка остаются открытыми.

## Задачи до production

**Выполнено** — реализовано и проверено в указанном объёме. **В процессе** — есть реализация или репетиция, остаются работы или приёмка. **Предстоит** — обязательная работа ещё открыта.

[Реестр v2.4](docs/spec/HostOrbit_Requirements_Registry_v2.4.json) определяет критерии. Первый сквозной сценарий — одна Ubuntu VPS, один импортированный тестовый Docker Compose-контейнер и ручной перезапуск через Change Plan. Управление Nginx, планировщик, отдельные центры хранения и уведомлений, расширенные веб-мастера и Support Bundle отложены. Nginx и Caddy остаются в объёме наблюдения.

### Stage2. Прогресс Change Plan для Docker restart

- [x] Предпросмотр перезапуска по наблюдению Docker.
- [x] Версионированные черновики с ETag и Audit/Outbox на копии БД.
- [x] Повторная проверка исходного наблюдения и сверка с новым завершённым `host.probe` в репетиции.
- [x] Постановка `host.probe` в очередь из черновика в репетиции, с защитой от дублей при повторе запроса.
- [x] Привязка результата preflight к заданию текущей ревизии и ключу запроса в журнале очереди. Ключ очереди защищён закрытым случайным значением ревизии.
- [x] Репетиция рассчитывает решение Backup Gate после preflight.
- [x] В ТЗ v2.4 задан класс для перезапуска подходящего тестового контейнера.
- [x] Owner подтверждает тестовый контейнер в конкретной ревизии черновика. Подтверждение записывается в Audit/Outbox.
- [x] SSH probe v5 проверяет mounts импортированного Docker-контейнера. Репетиция блокирует допуск при наличии mounts и при отсутствии достоверных данных.
- [x] SSH probe v6 проверяет сетевую изоляцию контейнера. Репетиция блокирует допуск при неизвестном или неизолированном состоянии.
- [x] SSH probe v7 проверяет зависимости на выделенном Docker-стенде. Репетиция подтверждает отсутствие требования к ResourceBackup для подходящей цели.
- [x] Решение Backup Gate на репетиционной копии записывается в Audit/Outbox и связывается с точной ревизией и наблюдением.
- [x] [Проверка опубликованного ControllerBackup](docs/stage1-migrations.md#предварительная-проверка-controllerbackup-для-рабочей-миграции) для текущей схемы и Controller с лимитом 30 минут.
- [x] Проверка полноты и целостности скачанного SFTP-комплекта по подписи и квитанции ControllerBackup.
- [x] [Повторная проверка миграции 2 → 3 на локальной тестовой БД](docs/stage1-migrations.md#проверка-сохранённой-репетиции) по схеме, данным и Audit/Outbox.
- [x] Чистая установка схемы 3 и HTTP API для черновика, preflight, Backup Gate и подтверждения Owner.
- [x] Репетиция подтверждения Owner с одноразовой повторной аутентификацией, привязкой к точной ревизии и решению Backup Gate в Audit/Outbox. Повторная проверка отклоняет заменённые ревизии и наблюдения.

Для разработки и CI используются Linux, Python 3.15 с SQLite ≥3.45 и закреплённые `age`/`age-keygen` v1.3.2 для crypto tests.

```sh
python3.15 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt -r requirements-quality.txt
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/ruff check .
.venv/bin/python tools/check_repository.py
.venv/bin/python -m unittest discover -s tests_tools -v
```

Команды остальных test suites и native CI приведены в CONTRIBUTING. Изменения проходят PR и CI; принятые evidence хранятся отдельно от текущих эксплуатационных инструкций.
