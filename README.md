# HostOrbit

Self-hosted система управления Linux-серверами по ТЗ v2.3. Прикладной Controller включает локальное создание Owner, Auth/RBAC, SQLite с Audit/Outbox, изолированные Worker/Broker, SSH observation, резервное копирование и восстановление.

## Текущее состояние

**До production проект не готов.** [Stage0 принят](evidence/acceptance/stage0-2026-11-07/README.md) по 15 обязательным проверкам прототипов. [Stage1 Foundation был принят](evidence/acceptance/stage1-2026-11-08/README.md) на исторической ревизии. На ревизии `4459cb2` прошли нативные проверки Docker, SSH и подписанной установки. [Обновлённые отчёты Foundation](evidence/revalidation/stage1-current/README.md) ссылаются на [ручной прогон HostOrbit CI](https://github.com/RoyMan810/HostOrbit/actions/runs/42856716693). [Отдельный сценарий потери исходной VM](https://github.com/RoyMan810/HostOrbit/actions/runs/42804027706) проверен на ревизии `722d486`. Stage2, независимый DR и полная приёмка MVP остаются открытыми.

Доступна подписанная **development**-установка на Ubuntu 24.04 и новее, amd64; native-установка проверена на 24.04 и 26.04. Единственный включённый remote adapter — read-only `host.probe`. Production mutations, A/B updates, live migration и независимая DR-приёмка остаются открытыми.

## Задачи до production

Статусы — снимок на 10.11.2026, а не автоматически обновляемый прогресс. **Принято** — есть указанное свидетельство на свой объём и ревизию; **подтверждено CI** — автоматические проверки прошли на указанной ревизии; **частично** — есть код или проверенный фрагмент, но задача целиком не принята; **открыто** — реализация и/или приёмка остаются невыполненными; **заблокировано** — нельзя безопасно включать до выполнения предусловий. Частичная реализация не означает `PASS` полного acceptance criterion (AC).

Таблица группирует все обязательные MVP-требования [реестра ТЗ](evidence/acceptance/stage0-2026-11-07/HostOrbit_Requirements_Registry_v2.3.json) по задачам; условия и зависимости отдельных AC зафиксированы в историческом реестре, а новые решения о приёмке отмечены ниже. Аппаратный профиль владельцем изменён на **1 vCPU / 2 GiB / 40 GiB**, но описание NFR-08 в историческом реестре пока содержит прежний профиль: согласование реестра с утверждённым ТЗ — отдельная задача ниже.

### Stage2. Прогресс восстановления Docker volume

- [x] Проверка подписанного архива и совместимости схемы, включая вчерашнюю точку восстановления.
- [x] Проверка подписанной Owner-аттестации процедуры со сроком 90 дней.
- [x] Проверка пустоты, отсутствия ссылок от контейнеров и ёмкости выбранного Docker volume. Повторная проверка по отпечатку отклоняет замену каталога тома с тем же именем и временем создания.
- [x] Офлайн-репетиция с ручной сверкой SHA-256. Резервирование нового приватного каталога, запись данных с исходными UID/GID/правами и отказ при повторном использовании цели.
- [x] [Лабораторный прогон на реальном Docker volume](https://github.com/RoyMan810/HostOrbit/actions/runs/42835202018) на `0b6a53c`. Восстановлены данные вчерашнего архива, проверены SQLite и отказ для занятой цели.
- [x] Запись из офлайн-консоли HostOrbit в новый Docker volume. Оператор подтверждает архив и имя цели. Перед записью проверяются резервирование, отпечаток тома и срок аттестации.
- [x] Владелец принял AC-B05 10.11.2026. [Прогон команды Rescue на Docker](https://github.com/RoyMan810/HostOrbit/actions/runs/42843283619) на `448c022` подтвердил восстановление вчерашнего архива, чтение SQLite и отказ при повторной записи. Проверенные изменения вошли в `main` через [PR #57](https://github.com/RoyMan810/HostOrbit/pull/57) в коммите `7b65934`.

Формальная проверка Stage2 по историческому снимку реестра по-прежнему показывает `NOT_RUN` для AC-28 и AC-B05. Решение владельца по AC-B05 зафиксировано выше.
