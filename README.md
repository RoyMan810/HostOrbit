# VPN-Orbit

Панель для управления VPS из браузера. Цель первой версии — подключение и подготовка сервера, развёртывание и обслуживание Remnawave Panel, Remnawave Node, Bedolaga Bot и Cabinet.

## Что уже работает

- **Контроллер и доступ.** Установка development-сборки, локальное создание учётной записи владельца, вход через HTTPS. Выделенный Nginx поддерживает локальный доступ через SSH-туннель и публичный домен с готовым сертификатом Certbot.
- **Инвентарь VPS.** Подключение заранее внесённых SSH-целей с проверкой отпечатка, проверка доступности и просмотр результатов наблюдения. Для зарегистрированных Docker-контейнеров видны состояние и опубликованные порты.
- **Операции на стенде.** Предпросмотр, подтверждение и перезапуск явно разрешённого тестового контейнера. В интерфейсе доступны результат операции, хронология и журнал аудита.

[Инвентарь и ограничения](docs/stage2-inventory.md) · [Руководство по веб-интерфейсу](web/README.md)

## Прогресс первой версии

**Ближайший этап** — закончить подготовку чистой VPS и подключение из браузера. Сейчас веб-интерфейс подключает заранее разрешённую и подготовленную цель и запускает SSH-проверку. Создание ограниченной сервисной учётной записи выполняется отдельным локальным CLI-инструментом; установка необходимых для сервисов зависимостей и весь процесс подготовки пока не доступны целиком через браузер.

| Задача | Статус | Как проверить завершение |
| --- | --- | --- |
| Установка контроллера и HTTPS через Nginx | Реализовано, нужна проверка на VPS | Проверить свежую установку на Ubuntu, вход через публичный домен и продление сертификата. |
| Наблюдение VPS и Docker-инвентарь | Готово для подготовленных VPS | В карточке видны результаты SSH-проверки, состояния зарегистрированных контейнеров и их порты. |
| Подтверждение и выполнение перезапуска | Готово для тестовой цели | На подготовленном стенде владелец подтверждает перезапуск и видит результат в хронологии. |
| Единая долговечная очередь операций | Реализовано, нужна проверка на VPS | Наблюдения и изменения используют общую очередь. После сбоя видно состояние задачи. Неизвестный результат требует сверки. |
| Подключение и подготовка чистой VPS | Частично реализовано | Веб-интерфейс подключает заранее разрешённую и подготовленную VPS по подтверждённому SSH-отпечатку и запускает проверку. Создание ограниченной сервисной учётной записи доступно отдельным CLI-инструментом; установка зависимостей и полный onboarding из браузера не реализованы. |
| Настройка firewall | Не готово для использования из интерфейса | Есть ограниченные компоненты протокола и удалённого исполнителя, но нет завершённого браузерного сценария настройки и приёмки. Планируемый контракт описан в [плане первой версии](docs/first-release.md#контракт-firewall). |
| Remnawave Panel и Node | Запланировано | Panel и Node развёртываются и настраиваются из VPN-Orbit. Первичная регистрация Node выполняется в Panel. |
| Bedolaga Bot и Cabinet | Запланировано | Работают HTTPS webhook, кабинет и проксирование его API через Nginx. |
| Подключение и удаление существующих установок | Запланировано | Владелец подтверждает известный Compose-профиль, видит внешние изменения и может убрать управляемые компоненты с сохранением данных и общих ресурсов. |

**За рамками первой версии** — резервное копирование и восстановление, перенос старой базы VPN-Orbit, обновление приложений и расширенный интерфейс аудита.

## Запуск development-сборки

Устанавливайте на чистую систему. Команды, службы, SSH-протокол и подписанные артефакты используют имена VPN-Orbit. Для ранее развёрнутой установки нужно отдельно перенести данные и заново подготовить SSH-профили.

На чистой Ubuntu Server 24.04 или 26.04 amd64:

```sh
git clone https://github.com/RoyMan810/VPN-Orbit.git
sudo ./VPN-Orbit/install
```

Установщик выведет локальный HTTPS URL, команду SSH-туннеля и путь к сертификату. Для публичного HTTPS используйте `--public-domain` с готовым сертификатом Certbot.
