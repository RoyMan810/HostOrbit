# HostOrbit

Self-hosted система управления Linux-серверами. Разработка начата с лабораторных прототипов Stage 0 по ТЗ v2.3.

## Допуск к изменениям

Первый прототип в `stage0/admission.py` покрывает локальную часть T0-4 (AC-B04 и AC-B09) и моделирует отложенный эффект из T0-1 (AC-B01).

- Перед имитацией инфраструктурной операции прототип сохраняет единственный допуск в локальной SQLite. Переход в `QUIESCING` закрывает выдачу новых допусков до возврата тикета. Обновление приложения и самообновление используют один механизм и ждут завершения текущей операции.
- Неопределённый исход сохраняется как `UNKNOWN_OUTCOME` вместе с открытым инцидентом. После решения владельца прототип блокирует всю VPS и транзитивно связанные хосты. При неполных сведениях о зависимостях сохраняется общий запрет. Открытый инцидент блокирует оба вида обновлений.
- После подтверждённой потери процесса лабораторный запуск вызывает `recover_after_restart()` до приёма запросов. Прерванное обновление или незавершённая операция переводят допуск в `RECOVERY_HOLD`.

Прототип использует временный файл SQLite и локальные процессы. Граф зависимостей задаётся тестами, результаты внешних действий имитируются. Для подтверждения AC-B01, AC-B04 и AC-B09 нужны стенд с Docker и SSH, независимый host supervisor и проверка свидетельств по ТЗ.

## Запуск тестов

На Linux с Python 3.13 и SQLite 3.45 или новее выполните команду из корня проекта.

```bash
python3.13 -m unittest discover -s tests -v
```

Тесты запускают независимые процессы для проверки гонки допусков, прерывают процессы через `SIGKILL` до и после фиксации транзакции и проверяют сохранение карантина после открытия журнала заново. Python-зависимости устанавливать не требуется.
