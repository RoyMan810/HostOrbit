# K-VPN Node Deployer

Установщик **новых серверов K-VPN** с Remnawave Node / Xray. Поддерживает входные ноды **RU** и выходные **Foreign**. Работает через меню: можно установить только нужный компонент, а не всё сразу.

> **Для новых VPS.** Не запускайте полную установку поверх работающих Node-RU, Node-NL или Host-Panel-NL. Работающий мониторинг автоматически не перезаписывается. Перед применением на production проверьте на тестовом VPS.

## Удобное меню в терминале (TUI)

Откройте меню на сервере (по SSH):

```bash
sudo bash kvpn-install.sh
```

Установщик открывает **полноэкранное меню с навигацией стрелками**, отдельными разделами и диалоговыми окнами. Нажмите `Enter` для выбора и `Esc` для возврата. Есть отдельные действия для Docker, ноды, UFW, HTTPS, резервного копирования и мониторинга. В мониторинге можно создавать **несколько независимых проверок** RU → Foreign, Foreign-local, регистрировать их SSH-ключи и проверять Telegram.

При первом запуске на минимальном Ubuntu установщик предложит установить небольшой системный пакет **`whiptail`** через APT. **`nano` не нужен.** Если экранный интерфейс недоступен, откроется резервное текстовое меню. Команды `preflight`, `status`, `monitor ru`, `monitor foreign` и остальные доступны и без TUI.

> **Важно:** запуск меню сам по себе не изменяет VPN. Изменения требуют выбора пункта и подтверждения. Установку Remnawave Node и первичную настройку UFW выполняйте **только на чистом VPS**; на рабочих нодах используйте только безопасные нужные действия. Уже работающий мониторинг не перезаписывается; новые проверки добавляются через соответствующие пункты меню.

## Что умеет

- **Проверка сервера** без изменений (`preflight`).
- **Docker + Compose** из официального APT-репозитория Docker.
- **Remnawave Node** из `docker-compose.yml`, выданного вашей Remnawave Panel.
- **UFW** — отдельная настройка SSH, Node API (только панель) и входных VPN-портов.
- **HTTPS для REALITY** — по желанию локальный nginx на `127.0.0.1:9444` и сертификат Let's Encrypt.
- **Резервные копии** — ежедневно, хранение 14 дней.
- **Мониторинг** — проверка TCP каждые ~5 минут и сообщения через отдельную мониторинговую панель в Telegram.
- **Статус и диагностика** — просмотр состояния без переустановки.

Для панели, профилей Xray, REALITY-ключей, маршрутизации и балансировки по-прежнему используется **Remnawave Panel**: установщик не настраивает их автоматически.

## Поддерживаемые системы

**Ubuntu 24.04 LTS, 26.04 LTS, 26.10** (64-bit); также Debian 12/13. Ubuntu 25.x исключены, поскольку уже сняты с поддержки. Поддержка ОС проверяется установщиком; полная установка на каждой из версий ещё не проверялась на реальном VPS.

На минимальном VPS **не нужен `nano`**: настройки вводятся в терминале, а мастер устанавливает необходимые пакеты. Если нет `curl`, сначала выполните `apt-get update && apt-get install -y curl ca-certificates`. Если отсутствуют утилиты распаковки, установите `coreutils tar gzip mawk`. Режим `preflight` ничего не устанавливает.

## Быстрый старт

**1.** Создайте новую ноду в Remnawave Panel и сохраните выданный `docker-compose.yml` на **новом** VPS, например `/root/new-remnanode-compose.yml`. В этом файле секрет — не загружайте его в GitHub.

**2.** Скачайте установщик:

```bash
curl -fL --proto '=https' --tlsv1.2 -o kvpn-install.sh \
  https://raw.githubusercontent.com/RoyMan810/kvpn-node-deployer/main/kvpn-install.sh
```

**3.** Проверьте сервер (ничего не меняет):

```bash
bash kvpn-install.sh preflight
```

**4.** Просмотрите исходники и откройте меню:

```bash
sudo bash kvpn-install.sh
```

В меню выберите, например: **только UFW**, **только Docker**, **только Remnawave Node**, **полная установка**, **резервные копии** или **мониторинг**. Для установки *только ноды* firewall с закрытым Node API необходимо подготовить заранее.

**5.** Завершите создание ноды и выберите **Config Profile** в Remnawave Panel. Проверьте конфигурацию REALITY и фактическое VPN-подключение.

## Несколько RU и Foreign нод

Установите пакет на **каждый новый сервер отдельно**. IP-адреса, порты и параметры вводятся при установке; ничего не привязано к одному RU/NL.

- На зарубежной ноде можно разрешить **несколько RU-адресов** для входящего Xray TCP-порта (через запятую без пробелов, например `192.0.2.10,198.51.100.20`).
- Позднее разрешить новый RU-адрес на *установленной этим пакетом* Foreign-ноде можно в меню **Add RU IP to foreign node UFW**, не меняя Docker/Xray.
- Мониторинг принимает **несколько уникальных Probe ID**: можно создать отдельную проверку `ru1-nl1`, `ru1-nl2`, `ru2-nl1`, `nl1-local` и т. п. На одной RU-ноде можно установить **несколько проверок** зарубежных серверов. Каждая использует отдельный SSH-ключ и таймер.
- На мониторинговой панели регистрируйте каждую проверку отдельно. При наличии K-VPN Monitor Kit можно добавлять новые Probe ID без переустановки работающей панели.

**Важно:** автоматического переключения клиентов между RU/Foreign нодами и балансировки в установщике **нет** — это настраивается отдельно в Remnawave/Xray.


## Проверка и безопасность

```bash
sudo bash kvpn-install.sh status
sudo bash kvpn-install.sh diagnostics
```

- Не запускайте полный мастер на действующих серверах.
- Перед изменением UFW убедитесь, что SSH доступен, и сохраните доступ к консоли провайдера.
- Не публикуйте Telegram-токены, REALITY/SSH-ключи, `docker-compose.yml` панели и архивы резервных копий.
- Проверка TCP-порта не доказывает работоспособность всего VPN.
- Для стабильных установок используйте проверенный коммит и SHA-256 вместо изменяемой ветки `main`.
