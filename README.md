# K-VPN Node Deployer

Переносимый установочный комплект для **новых** VPS с Remnawave Node и Xray, с опциональными локальной HTTPS-заглушкой для REALITY, UFW, резервными копиями и K-VPN Monitor Kit. Поддерживает **входные ноды в РФ** (`ru`) и **выходные ноды за рубежом** (`foreign`).

**Важно:** это не заменяет Remnawave Panel и не загружает конфигурации Xray на сервер самостоятельно. Профили, ключи REALITY, SNI, inbounds, outbounds, пользователи, подписки и маршруты настраиваются **в панели Remnawave**. Установщик принимает готовый `docker-compose.yml`, полученный именно из вашей панели, чтобы не угадывать формат `SECRET_KEY`/`SSL_CERT`.

## Скачать из GitHub

**Проверяйте исходники перед запуском под root.** На чистом VPS можно загрузить один самораспаковывающийся файл (без входа в GitHub):

```bash
curl -fL --proto '=https' --tlsv1.2 \
  -o kvpn-install.sh \
  https://raw.githubusercontent.com/RoyMan810/kvpn-node-deployer/main/kvpn-install.sh
bash kvpn-install.sh preflight
sudo bash kvpn-install.sh wizard
```

Для воспроизводимой установки в production используйте ссылку на **конкретный проверенный коммит** вместо ветки `main`, сверяйте SHA-256 и избегайте `curl | bash`. Исходники и тесты доступны в этом репозитории.

**Примечание о безопасности:** репозиторий публичный, поэтому реальных IP, доменов, токенов, приватных ключей, SSH-ключей и панельного `docker-compose.yml` здесь нет. Для новой ноды нужно вводить адреса вручную и вставлять compose с секретом только на самом сервере.

## Что делает пакет

1. Проверяет ОС, RAM, swap, порты, существующие установки (команда `preflight` ничего не меняет).
2. На **новом сервере** по согласованию устанавливает Docker Engine и Compose с официального установщика Docker. Устанавливает Python, SSH client, curl, UFW.
3. Проверяет, что YAML для `remnanode` использует официальный контейнер, `network_mode: host`, API-порт совпадает с вводом и есть секрет панели. Значение секрета не печатается.
4. Настраивает UFW: разрешает текущий порт SSH, Remnawave Node API **только с IP панели**, а порт Xray — с заданного IP/диапазона. Если включает UFW впервые, устанавливает политику `deny incoming`. Не удаляет уже имеющиеся правила. Не заменяет SSH-конфигурацию.
5. Разворачивает `/opt/remnanode/docker-compose.yml` с правами `600` и запускает контейнер. Не меняет действующий стек, если compose уже существует.
6. По выбору создаёт 1 GiB swap на VPS с RAM <1 GiB, если нет swap и хватает места.
7. По выбору устанавливает ежедневную архивную копию настроек (`/root/server-backups`, права `600`, sha256, хранение 14 дней). Архивы содержат секреты!
8. По выбору создаёт HTTPS-сайт-заглушку `127.0.0.1:9444` с сертификатом Let's Encrypt для REALITY. **Не** настраивает inbounds/outbounds автоматически.
9. По выбору вызывает **встроенный K-VPN Monitor Kit**: `panel` (на **новой** панели), `ru` или `foreign` (на **новых** нодах). Агенты мониторинга проверяют TCP и отправляют результаты в мониторинговую панель по SSH.

## Требования

- Чистый VPS Ubuntu/Debian с systemd, root SSH-доступом и прямым доступом в Интернет; рекомендуется >= 1 GiB RAM, >= 1 vCPU (требования Remnawave Node).
- Установленная **отдельно** Remnawave Panel, где вы можете создать новую ноду и скопировать её `docker-compose.yml`.
- Известные: IP панели, выбранный Node API порт (обычно `2222`), входной TCP-порт Xray и разрешённый источник этого TCP-трафика.
- Текущий порт SSH; при наличии панели управления VPS желательно иметь доступ к аварийной консоли на случай неверных UFW-правил.
- Для опциональной HTTPS-заглушки: доменное имя с A-записью на **новый** сервер, email, внешний доступ к TCP 80 для выдачи/обновления сертификата, свободные порты 80 и 9444. По умолчанию открывается 80 при выборе ACME.

## Самый простой путь: одна команда установки

Распакуйте архив на **новом** сервере:

```bash
sudo mkdir -p /root/kvpn-deployer
sudo tar -xzf kvpn-node-deployer.tar.gz -C /root/kvpn-deployer
cd /root/kvpn-deployer/kvpn-node-deployer
sudo ./install.sh preflight
```

Перед запуском мастера в **Remnawave Panel** откройте `Nodes → Management → +`, заполните ноду и нажмите **Copy docker-compose.yml**. Сохраните этот YAML на новом сервере, например в `/root/new-remnanode-compose.yml` (используйте `nano`, `scp` через защищённый канал или SFTP; **не публикуйте содержимое**, в нём секрет панели). В панели **ещё не завершайте** создание ноды, пока контейнер не поднят.

Затем:

```bash
sudo ./install.sh wizard
```

Мастер спросит:
- `ru` или `foreign`;
- IP панели (**обязательно вводится при установке**, без предустановленного адреса);
- Node API порт из YAML (`2222` по умолчанию);
- TCP-порт Xray (для зарубежной ноды обычно `8443`; для РФ задаётся вашим профилем/прокси);
- допустимый IP-источник для входного транспорта (для зарубежной ноды укажите IP вашего российского узла, для публичной RU-ноды `0.0.0.0/0`);
- текущий SSH порт и нужен ли ACME;
- путь к YAML, затем **явное подтверждение** Docker/UFW;
- отдельно — резервное копирование, HTTPS-заглушку и опционального агента мониторинга.

Установщик не выполняет автоматические изменения панели. После запуска контейнера вернитесь в Remnawave Panel, завершите создание ноды и привяжите **нужный Config Profile**. Проверьте исходные/входные маршруты Xray, SNI/Reality, ключи и клиентское подключение. `docker compose ps` показывает только контейнер, а не работоспособность VPN.

### Российская входная нода (RU)

Если за публичным `443/tcp` стоит nginx, а Xray слушает `10000`, мастер **не устанавливает и не подменяет** nginx-прокси/REALITY/маршрутизацию: их параметры зависят от профиля. Выберите порт, который реально должен быть доступен извне; настройте дополнительные локальные слушатели вручную. Убедитесь, что внешний IP и порт входят в конфигурацию клиентского Host панели.

### Зарубежная выходная нода (Foreign)

Обычно нужно разрешить `8443/tcp` **только с IP RU-ноды**. В Remnawave задайте соответствующий Reality inbound и outbound `NL_PROXY` на RU, SNI и serviceName gRPC; серверный REALITY target можно направить на локальную заглушку `127.0.0.1:9444` (если она установлена). Домен и SNI должны соответствовать настройкам вашего сервера. Для смены IP укажите новый адрес в RU outbound и проверьте выходной IP клиента.

### HTTPS REALITY заглушка

Если ACME на этапе мастера был отложен, позже на **новой** ноде:

```bash
sudo ./install.sh decoy
```

Операция рассчитана на **новый сервер без другого веб-сайта на 80/9444**. Сертификат получает `certbot --standalone`, nginx слушает только `127.0.0.1:9444`. Подключение к интернету и сертификат проверяются с `curl --resolve`. HTTP-порт `80` должен оставаться доступным при автоматическом обновлении сертификата. При конфликте с чужим nginx установщик останавливается без перенастройки чужого сайта.

## Резервные копии

```bash
sudo ./install.sh backup
sudo systemctl status kvpn-node-backup.timer --no-pager
sudo journalctl -u kvpn-node-backup.service -n 20 --no-pager
sudo ls -lah /root/server-backups/
```

Резервная копия содержит `/opt/remnanode`, UFW/SSH/nginx/Let's Encrypt и установочные конфиги, если они существуют. Права root-only. Хранение 14 дней. Не помещайте архивы с ключами в публичный GitHub или в незащищённое облако. Чтобы обновить существующую настроенную ноду, пользуйтесь штатными обновлениями Docker/Remnawave после бэкапа, **не** запускайте мастер заново.

## Мониторинг (отдельный компонент)

В архив включён `monitor-kit`, который может устанавливаться отдельно:

```bash
# На НОВОЙ мониторинговой панели (не на текущей Host-Panel-NL):
sudo ./install.sh monitor panel

# На НОВОЙ RU-ноде:
sudo ./install.sh monitor ru

# На НОВОЙ зарубежной ноде:
sudo ./install.sh monitor foreign

# На НОВОЙ мониторинговой панели после установки агента:
sudo ./install.sh monitor register
```

Агент `ru` проверяет TCP-выход из России до зарубежного адреса; агент `foreign` проверяет локальный порт и не доказывает сетевую доступность из РФ. В обоих случаях отчёт отправляется по **отдельному прямому SSH**, без использования VPN. Для каждого агента регистрируется отдельный ограниченный SSH-ключ; указывайте уникальный Probe ID. Таймер проверки ~5 минут, оценка панели ~1 минута, тревога после 2 неудач, статус `UNKNOWN` без отчётов >720 секунд, восстановление после 1 успеха. Telegram-топик задаётся при установке мониторинговой панели.

**КРИТИЧЕСКИ ВАЖНО ДЛЯ ТЕКУЩЕГО K-VPN:** на сервере действующей панели может быть запущен **старый, работающий мониторинг** в `/root/kvpn-monitor` и `kvpn-monitor.timer`. Старый обработчик принимает **один общий статус** и не поддерживает несколько независимых Foreign/RU Probe ID. Новый комплект **не мигрирует его** и должен отказываться от перезаписи. НЕ запускайте `monitor panel` на работающей панели. Для добавления нескольких источников нужно **отдельно запланировать миграцию** агрегатора/бота и ключей, проверив переход без прерывания уведомлений. До миграции действующая RU-проверка продолжит работать без изменений.

Если новая зарубежная нода заменит нынешнюю, на текущей RU-нôде старый монитор проверяет конкретный IP, его нужно будет согласованно обновить после проверки маршрута. Два комплекта мониторинга не должны одновременно записывать один и тот же `latest.status`.

## Команды обслуживания

```bash
sudo ./install.sh status
sudo ./install.sh diagnostics
cd /opt/remnanode && sudo docker compose ps
sudo journalctl -u kvpn-node-backup.service --since today --no-pager
sudo ./install.sh monitor status
```

`diagnostics` сохраняет локальный текстовый файл без содержимого YAML, токена и ключей; в нём могут быть IP-адреса — проверьте перед пересылкой. Скрипт не собирает Docker/Xray логи с потенциальными секретами.

## Безопасность и пределы автоматизации

- Установка предназначена **только для нового сервера**. Если обнаружен `/opt/remnanode/docker-compose.yml`, мастер прекращает работу.
- Не отключается вход по SSH и не меняются ключи или настройки `sshd` (исключает риск самоблокировки); для полноценного hardening убедитесь, что SSH по ключу работает, и выполните отдельную процедуру.
- Все существенные сетевые изменения требуют подтверждения в интерактивном TTY. При незнакомых настройках VPS/UFW используйте доступ к консоли провайдера.
- Docker на Linux может изменять правила netfilter; для Node используется `network_mode: host`, а Node API ограничивается UFW. Проверяйте правила на реальном сервере после установки.
- Пароли, токены, приватные REALITY-ключи, Bot Token и секреты панели **не включены в этот архив**. Compose от панели хранится на устанавливаемом сервере с правами `600`.
- `REALITY/gRPC/XHTTP`, `NL_PROXY`, балансировщики и клиентские ссылки задаются в Panel: автогенерация этих конфигураций небезопасна без актуальных ключей и API-состояния.
- При 2 FAIL по 5 минут оповещение придёт не мгновенно; это выбранный компромисс по нагрузке. Мониторинг TCP ≠ проверка полноценного VPN.
- Заменить зарубежную ноду без смены доступа пользователей можно, только если сохранился рабочий входной RU Host и корректно перенастроен RU outbound.
- Не запускайте сторонние установщики из непроверенных источников без просмотра исходного кода и резервной копии.
