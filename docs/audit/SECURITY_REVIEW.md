# Обзор безопасности и модель угроз

База, все ID замечаний и подтверждения — в [AUDIT_REPORT](AUDIT_REPORT.md). Этот документ не является полным penetration test и не утверждает отсутствие уязвимостей.

## Активы, нарушители и доверие

Активы: Owner и сессии, approved plans и права на цели, SSH-ключи/DEK, целостность Audit и backups, управляемые VPS, подписанные исполняемые артефакты. Учитываются посторонний Web-клиент, пользователь с ограниченной ролью, контролируемый/скомпрометированный VPS и ошибочный оператор. Риски компрометации репозитория, индексатора зависимостей или build host относятся к цепочке поставки.

ТЗ §31 явно помещает Backend в TCB: произвольное выполнение кода с правом менять авторитетную БД не нейтрализуется независимой криптографической проверкой пользовательского approval. Root, Docker daemon управляемой VPS и заведомо ложное Owner attestation также за пределами полной гарантии. Подпись Audit/backup не защищает от компрометации соответствующего доверенного signing key.

## Границы и результаты

| Граница | Проверенное | Что остаётся |
|---|---|---|
| Интернет → API | Origin/HTTPS/Host, ограничение тела, cookie/CSRF, серверные сессии и RBAC: [api.py](../../hostorbit/api.py), [auth.py](../../hostorbit/auth.py). 75 тестов API прошли. | Настоящий reverse proxy/TLS и распределённые атаки в этом аудите не испытывались; XSS проверен по выбранным потокам, не полным сканированием. |
| API → Worker/БД | Transactional Job + Audit/Outbox и повторная проверка прав при claim/advance. В API нет общего endpoint исполнения команд. | Любой Backend-RCE в пределах TCB может менять авторитетные данные. Не заявлять независимое approval. |
| Worker → Gate/Broker | SO_PEERCRED и ограниченные операции [ipc.py](../../hostorbit/runtime/ipc.py), scope/nonce/epoch в [authority.py](../../hostorbit/runtime/authority.py); Vault use связан с purpose, UID и target. | Реальный тест разграничения UID не повторён локально; прошедший job GitHub не является новым независимым pentest. |
| Broker → VPS | Числовой IP/scope policy, pinned Ed25519 host key, фиксированные команды и ограниченный вывод [ssh.py](../../hostorbit/runtime/ssh.py). | Компрометированная управляемая ОС может лгать в своих ответах; полная ручная проверка helper/sudoers и всех downgrade-сценариев не завершена. |
| Backup/Rescue | Подпись provenance, age, отдельный offline identity, размерные ограничения и read-only recovery. | AUD-02: producer/consumer не согласуют предельный размер. Независимый DR и физическая изоляция старого Controller не проводились. |
| Release → установка | Проверка подписи и фиксированных хешей артефакта; [`build_bundle.py`](../../deploy/build_bundle.py) подписывает сформированный состав. | AUD-03: сборка не доказывает заранее доверенный состав входных wheels и пропускает untracked при проверке чистоты. Это риск цепочки поставки, не доказанная эксплуатация. |

SQL-запросы рассмотренных путей параметризованы; произвольный shell из API не найден. Это не подтверждение, что во всём репозитории отсутствуют SQL injection, command injection, path traversal или SSRF. Тайминги, конкурентные отзыв/dispatch, многопользовательский нагрузочный тест и security fuzzing в этом аудите не выполнены.

## Приоритеты безопасности

- **AUD-03 (P1, риск):** чистый воспроизводимый исходный состав и заранее проверяемые hashes dependencies до подписи.
- **AUD-02 (P1, отказ восстановления):** общий контракт архивов по размеру; не смешивать signed и restore-attested.
- **AUD-01 (P1, assurance):** пересобрать доказательства на текущем commit, не заменяя архивные evidence.
- **AUD-04 (P2, восстановление истории):** атомарное карантинное событие с сохранением цепочки и исходного состояния.

## Обязательные дальнейшие испытания

Независимый review угроз после реализации изменяющих adapters; негативные проверки между реальными UID и sockets, подмена пакетов/manifest и host key, проверка replay/expiry, revoke между preflight и dispatch, потеря связи на каждом checkpoint, восстановление на отдельной машине, проверка содержимого логов/ошибок на секреты, ручной аудит конфигурации HTTPS proxy. Гипотезы не считать найденными уязвимостями, пока не получен воспроизводимый контрпример.
