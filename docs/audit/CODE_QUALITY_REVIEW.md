## Где сложность обоснована

Подписи, раздельные UID, host gate, durable intent до dispatch и read-only recovery не являются лишними слоями сами по себе: они обеспечивают конкретные границы из ТЗ. Замена этих механизмов общим HTTP-клиентом или прямым SSH из API была бы короче, но потеряла бы существенные гарантии.

Stage0 и связанные тесты частично похожи на runtime, но тестируют отдельные лабораторные гипотезы и закреплены приёмкой. Удалять их как дубликаты нельзя без сохранения assertions и доказательств.

## Что упрощать после доказательства

- Свести правила записи терминальных Job/Audit в одном транзакционном контракте для обычного выполнения и импорта, не вводя framework для одного случая.
- Привести ограничения размеров архива к одному контракту producer/consumer; не копировать числовые лимиты в новые компоненты.
- Сохранить текущие typed validators и pinned dependencies; не добавлять ORM, DI-контейнер или брокер очередей ради количества модулей.
- Декомпозиция больших функций оправдана только если отдельно тестируются реальные обязанности: например, сборка capture, проверка целостности и публикация. Сам размер функции или граф вызовов не доказывает дефект.

Не найдено доказанного неиспользуемого production-компонента, который безопасно удалить по результатам этого ограниченного анализа. Полный поиск динамических ссылок и ручной аудит каждого модуля остаются невыполненными.
