# Приёмка AC-28 владельцем

Владелец 20 ноября 2026 года принял AC‑28 по результатам локального прогона и согласовал закрытие Stage2. Controller, управляемая Ubuntu VM и SFTP размещались на одном физическом ПК. На этот прогон владелец утвердил исключение по отдельной VPS и независимому SFTP-хранилищу. AC‑B05 принят ранее. [Свидетельство AC‑B05](../../tests/ac-b05.json)

Использовалась подписанная development-сборка из коммита [e4d1f23](https://github.com/RoyMan810/HostOrbit/commit/e4d1f237ec1891365751da184d7f6d25aa46cf52). SHA‑256 её манифеста `938882977ee700e5e05b2fea15776ca03c616c00052d675903ad16efd87f6f18`. Вывод команд и состояние интерфейса предоставил владелец.

| Проверка | Наблюдаемый результат |
|---|---|
| Первое подключение | На чистом Controller создан Owner. Управляемый хост зарегистрирован по проверенному Ed25519-отпечатку. Через WebUI получено успешное SSH-наблюдение одного контейнера `restart-lab / fixture`. |
| Первый перезапуск | Docker подтвердил новый `StartedAt` `2026-11-19T20:21:28.259150022Z`. Удалённая квитанция `01M7TQGPN4T3J587XMCR5TMPJA.verified` сохранилась. Controller записал `UNKNOWN_OUTCOME / SSH_RESTART_REPLY_INVALID`. Ручная сверка сохранила блокировку, автоматического повтора не было. Ошибка ответа возникла при работающем SSH. |
| Исправление | Для служебных SSH-аккаунтов созданы домашние каталоги. Probe v8 прошёл без `Could not chdir`. Пустой запрос на перезапуск отклонён кодом 65 без предупреждений. |
| Повторный перезапуск | На чистом Controller ревизия плана 1 прошла очередь, подготовку и отправку. В Timeline в 02:01:15 по Екатеринбургу зафиксирован `DOCKER_RESTART_VERIFIED`. Docker показал `StartedAt` `2026-11-19T21:01:15.094192794Z`, тот же полный ID контейнера и статус `running`. |
| ControllerBackup | Снимок `01M7TR8YQ3S0D68GC13RJZBYP2` создан на первом Controller и опубликован по защищённому SFTP. Ответ `PUBLISHED` подтвердил обратное чтение. Скачанная копия совпала по SHA‑256 `0bfbe414f51b3afc84513ce60545656eb9df97942b3bae6830ab4f1c475b5640` и расшифровалась ключом владельца. |

Первый инцидент остался в журнале старого Controller. Прямой разрыв SSH после передачи команды и полный набор отрицательных сценариев в этом локальном прогоне не воспроизводились. Полное восстановление Controller и независимый аварийный контур относятся к отдельной приёмке.
